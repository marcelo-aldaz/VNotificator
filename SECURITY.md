# Security Policy

Do not report vulnerabilities with real student records, credentials, tokens,
database dumps, or production URLs in a public issue.

Until a dedicated security contact is published, report suspected
vulnerabilities privately to the institutional Moodle administrator and the
software maintainer. Include the release, Moodle version, PHP version, database
type, reproduction steps using synthetic data, and the expected/observed result.

Supported security fixes target the most recent stable V9.4.x release. A public
security contact and disclosure window must be added before repository launch.
