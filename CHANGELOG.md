# Changelog

## 1.3.9.14 — V9.4.2 stable (2026-07-18)

- Aligned Moodle maturity metadata with `MATURITY_STABLE` and incremented the
  metadata-only build to `2026071807` before the public release.
- Promoted the production-accepted RC5 logic without analytical or schema
  changes.
- Recorded successful Moodle web-interface validation of follow-up, novelty
  creation and closure, institutional aggregation, consecutive-period trend,
  and Spanish dashboard presentation.
- Incremented the Moodle build for web upgrade over RC5.

## 1.3.9.14 — V9.4.2 release candidate 5 (2026-07-18)

- Added a single Apply and recalculate dashboard action to avoid recalculating
  a previously loaded period by mistake.
- Enhanced trends within the same semaphore band using a five-percentage-point
  margin in the unique high-risk student rate.
- Replaced misleading temporal curve descriptions with categorical risk-profile
  wording in dashboards and institutional reports.
- Added matching English, Spanish, and Latin American Spanish interface strings.
- Incremented the Moodle build for web upgrade over RC4.

## 1.3.9.14 — V9.4.2 release candidate 4 (2026-07-18)

- Corrected period-end open-case calculation so a novelty whose current status
  is closed and whose legacy closure timestamp is missing is not counted open.
- Preserved historical semantics for cases closed after the end of the analysed
  period.
- Ensured novelties created directly with closed status receive closure time
  and responsible-teacher metadata.
- Incremented the Moodle build for web upgrade over RC3.

## 1.3.9.14 — V9.4.2 release candidate 3 (2026-07-18)

- Restored the missing case-resolution form in the teacher-facing student
  profile by loading open and reviewed novelties before rendering the page.
- Validated that a submitted novelty belongs to the student and course shown
  before allowing its status or resolution evidence to be updated.
- Restricted institutional trend comparison to prior aggregates generated by
  the same V9.4.2 analytics semantics.
- Incremented the Moodle build so RC3 can be installed over RC2 from the web
  plugin installer without uninstalling the production data.

## 1.3.9.14 — V9.4.2 release candidate 2 (2026-07-18)

- Corrected Moodle enrolment date column names from `enrolstart`/`enrolend`
  to `enrolstartdate`/`enrolenddate` after the RC1 recalculation failure.
- Incremented the Moodle build so RC2 can be installed over RC1 from the web
  plugin installer.

## 1.3.9.14 — V9.4.2 release candidate 1 (2026-07-18)

- Changed the institutional unit of analysis to unique students while retaining
  student-course observations as a separate metric.
- Restricted the monitored population to student roles and enrolments/courses
  overlapping the selected reporting period.
- Made inactivity deterministic against the period cut-off instead of the
  server execution time for closed periods.
- Separated notification delivery, pedagogical follow-up, and open case data.
- Calculated follow-up coverage only from human follow-up records.
- Added explicit unassigned tutor and cohort buckets and removed arbitrary
  minimum-ID assignment.
- Added institutional trend calculation against the previous chronological
  period and corrected the last-consolidation timestamp.
- Replaced misleading line comparisons with bar charts.
- Added pseudonymised critical-case views/exports and a manager-only capability
  for identified institutional reports.
- Added aggregation tests, a data dictionary, and a production validation gate.

## 1.3.9.13 — V9.4.1 stable candidate (2026-07-18)

- Preserved production release 1.3.9.12 as the immutable baseline.
- Aligned internal analytics source version with V9.4.1.
- Expanded Moodle Privacy API coverage for risk, follow-up, and novelty data.
- Added open-source license and citation metadata.
- Replaced the outdated prototype README with reproducible installation notes.
- Added architecture, privacy, quality-control, reuse, and Human-in-the-Loop documentation.
- Added initial PHPUnit coverage for deterministic risk classification behaviour.

## 1.3.9.12 — V9.4.0 candidate stable (2026-05-16)

- Production baseline supplied by the maintainer.
- Consolidated service loading and package metadata.
- Included an internal technical audit record.
