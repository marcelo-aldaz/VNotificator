# Contributing

1. Create an issue describing the defect or proposed change without personal data.
2. Base changes on the current stable branch.
3. Follow Moodle coding style and use the `local_pceinotifications` namespace.
4. Add or update PHPUnit/Behat coverage for behavioural changes.
5. Run Moodle code checks, PHPUnit, Privacy API tests, and the staging checklist.
6. Document user-visible changes in `CHANGELOG.md`.

Contributors must confirm that submitted code can be distributed under
GPL-3.0-or-later.
